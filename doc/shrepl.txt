1. INTRO                                                       *shrepl-intro*

shrepl keeps one bash process alive per Neovim session and sends it the
command under your cursor. Variables, functions and the working directory
survive between evaluations. The result appears at the end of the evaluated
line (`=> output`, or `✗ <exit code>` in red), longer output opens in a
float, and every evaluation lands in a log buffer.

Works in any buffer: a shell script, a Markdown runbook, a scratch buffer.

==============================================================================
2. SETUP                                                       *shrepl-setup*

>lua
  require('shrepl').setup({
    shell = { 'bash', '--norc', '--noprofile' },
    env = { PAGER = 'cat', GIT_PAGER = 'cat', AWS_PAGER = '', TERM = 'dumb' },
    float = { max_height = 20, max_width = 140, border = 'rounded' },
    signs = { running = '·', ok = '✓', fail = '✗' }, -- or false
    log = { split = 'botright 15split', vsplit = 'botright vsplit' },
    mappings = { eval_command = '<localleader>ee' }, -- see below; false disables
  })
<
The commands in |shrepl-commands| work without calling setup().

                                                              *shrepl-confirm*
confirm   Before running, every logical line (`\` continuations joined) is
          lowercased and checked against `confirm.patterns` (defaults in
          `require('shrepl').default_confirm`) plus `confirm.add`. Entries are
          Lua patterns or functions `fn(line) -> bool`. A hit shows the line
          and asks; Cancel marks it `⊘ not run`. `patterns` replaces the
          defaults, `add` extends them, `confirm = false` disables the check.
          It is a guardrail for runbooks, not a sandbox: variables, aliases
          and scripts can still do anything.

==============================================================================
3. MAPPINGS                                                 *shrepl-mappings*

  Key                 Option            Action ~
  <localleader>ee     eval_command      current line, plus following lines while
                                        a line ends in `\`, `|`, `||` or `&&`
  <localleader>er     eval_block        lines around cursor up to blank lines,
                                        or the whole fenced block (see below)
  <localleader>eb     eval_buffer       whole buffer
  <localleader>E      eval_selection    visual selection
  <localleader>eo     open_last         last result in a scratch split
  <localleader>ls     log_split         toggle log (horizontal)
  <localleader>lv     log_vsplit        toggle log (vertical)
  <localleader>ei     interrupt         SIGINT the running command
  <localleader>eR     restart           kill the shell; next eval starts fresh
  <localleader>ec     clear             clear inline results

                                                              *shrepl-fences*
Inside a Markdown fence (``` or ~~~), eval_block runs the fence body, blank
lines included, with the fence's own indentation removed. Fences tagged sh,
bash, shell, zsh, console ({bash} and {.bash} too) or untagged count as shell;
other languages are refused with a warning. Outside fences, fence lines end a
block.

==============================================================================
4. COMMANDS                                                 *shrepl-commands*

  :[range]ShreplEval    evaluate [range] (default: current line)
  :ShreplLog            toggle the log window
  :ShreplLast           open the last result in a scratch split
  :ShreplInterrupt      SIGINT the running command
  :ShreplRestart        restart the shell
  :ShreplClear[!]       clear inline results in the current buffer; with !
                        also the ✓/✗ signs showing which lines already ran

==============================================================================
5. CAVEATS                                                   *shrepl-caveats*

- stdin is /dev/null, so interactive programs (prompts, less, top) won't
  work. Use |:terminal| for those.
- The shell starts with --norc: your aliases aren't there, PATH and the
  environment are inherited from Neovim.
- Output is collected line by line; carriage-return progress bars show up
  once they print a newline.
